三大知识体系已经梳理完毕。下面是 DataAgent 中「语义模型配置」「业务知识配置」「智能体知识库构建与召回」的核心流程全貌。

## 一、总览：三类知识的定位差异

| 维度 | 语义模型 | 业务知识 | 智能体知识库 |
|---|---|---|---|
| 定位 | 表/字段 → 业务名、同义词、描述的映射 | 业务术语定义（如 PV、KMV） | 文档 / QA / FAQ 的 RAG 知识 |
| 是否向量化 | ❌ 不进向量库 | ✅ 进向量库 | ✅ 切分后进向量库 |
| 生效方式 | 选表后按表名精确查询拼 Prompt | 检索时按 `isRecall=1` 动态过滤 | 同左，按 `isRecall=1` 过滤 |
| 消费节点 | 表关系推理 / SQL 生成 | 证据召回节点 → 全流程节点 | 同左 |

## 四、智能体知识库构建（异步事件驱动）

**构建侧流程：** [AgentKnowledgeServiceImpl.java](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/service/knowledge/AgentKnowledgeServiceImpl.java#L64-L89)

```
createKnowledge（前端 createWithFile 走 FormData 上传）
  → DOCUMENT 类型：FileStorageService.storeFile 落盘，记录 file_path/splitter_type
  → insert agent_knowledge 表（embedding_status=PENDING）
  → 事务提交后 publish AgentKnowledgeEmbeddingEvent
        ↓ @Async + @TransactionalEventListener(AFTER_COMMIT)   ← 事务提交后才异步执行
  AgentKnowledgeEventListener.handleEmbeddingEvent (L45-76)
        → PROCESSING → AgentKnowledgeResourceManager.doEmbedingToVectorStore → COMPLETED / FAILED
```

**向量化核心：** [AgentKnowledgeResourceManager.java](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/service/knowledge/AgentKnowledgeResourceManager.java#L55-L115)

- **QA/FAQ**：`convertQaFaqKnowledgeToDocument` 整体转 Document（问题作为文本，metadata 带 `concreteAgentKnowledgeType`）；
- **DOCUMENT**：`TikaDocumentReader` 读文件 → `TextSplitterFactory.getSplitter(splitterType)` 切分 → 补元数据 → `replaceDocumentsByMetadata`；
- 分块策略：`token / recursive / sentence / paragraph / semantic`（semantic 用 EmbeddingModel 计算语义相似度确定切分点），未命中回退 token；
- 删除：逻辑删除 + `AgentKnowledgeDeletionEvent` 异步清理向量和文件（`is_resource_cleaned` 标记，定时任务兜底）；`retryEmbedding` 重置 PENDING 后重新发布事件。

**向量元数据规范**（[DocumentMetadataConstant.java](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/constant/DocumentMetadataConstant.java)）：

| vectorType | 定位字段 |
|---|---|
| `agentKnowledge` | `agentKnowledgeId` + `concreteAgentKnowledgeType` |
| `businessTerm` | `businessTermId` |
| `table` / `column` | `datasourceId` + `name/tableName` |

## 五、召回核心流程（统一入口 + 动态过滤 + 混合检索）

**图节点入口：** [EvidenceRecallNode.java](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/workflow/node/EvidenceRecallNode.java)（位于 `IntentRecognition → EvidenceRecall → QueryEnhance → …` 链路上）

```
① LLM 查询重写：多轮上下文 + 原始问题 → buildEvidenceQueryRewritePrompt
   产出 standaloneQuery（不扩展子查询，避免专业名词引入噪音）
② 双路召回：
   getDocumentsForAgent(BUSINESS_TERM)   ← 业务知识
   getDocumentsForAgent(AGENT_KNOWLEDGE) ← 智能体知识库
③ 格式化证据：[来源: 标题-文件名] 内容 / Q:xxx A:xxx（FAQ/QA 从 DB 回查答案）
④ 写入 state 的 EVIDENCE，向下游节点流转
```

**检索链路：** [AgentVectorStoreServiceImpl.search](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/service/vectorstore/AgentVectorStoreServiceImpl.java#L74-L104)

1. `DynamicFilterService.buildDynamicFilter(agentId, vectorType)`：基础条件 `agentId == x AND vectorType == y`，再查 MySQL 拿 `isRecall=1 且未删除` 的 ID 列表，拼 `id IN (...)` 条件；**若列表为空直接返回空结果，不走向量库**；
2. 若开启 `enableHybridSearch` → `HybridRetrievalStrategy`（向量 + 关键词融合）；否则纯 `similaritySearch`（topK + 相似度阈值）；
3. 底层支持 Milvus / Elasticsearch / SimpleVectorStore（默认内存兜底 [DataAgentConfiguration.java](file:///D:/workspace_open/DataAgent/data-agent-management/src/main/java/com/alibaba/cloud/ai/dataagent/config/DataAgentConfiguration.java#L345-L351)），精确元数据检索由 `MetadataDocumentRetriever` 做 provider 适配。

**EVIDENCE 的下游消费点**（证据注入各节点 Prompt）：

| 节点 | 用途 |
|---|---|
| QueryEnhanceNode | 查询增强 |
| TableRelationNode | 选表推理（同时用语义模型 Prompt） |
| FeasibilityAssessmentNode | 需求可行性评估 |
| PlannerNode | 计划生成（同时用语义模型 Prompt） |
| SqlGenerateNode | SQL 生成的 `evidence` 字段 |
| SemanticConsistencyNode | SQL 语义一致性校验 |

## 六、关键差异点总结

1. **构建路径不同**：语义模型纯 MySQL 同步 CRUD；业务知识同步双写（DB + 向量库）；智能体知识库「先落库、后异步向量化」（事件 + 事务提交后触发，支持失败重试）。
2. **召回控制设计统一**：业务知识和智能体知识库都通过 `isRecall` 开关 + `DynamicFilterService` 检索时动态过滤，避免开关操作直接改向量库。
3. **失效治理**：向量更新统一用 `replaceDocumentsByMetadata`（先写后删）；删除走逻辑删 + 异步资源清理 + 定时兜底。
4. **证据合并**：`EvidenceRecallNode` 把业务知识和知识库文档合并为一份带来源标注的 EVIDENCE，一次召回、全链路复用。
